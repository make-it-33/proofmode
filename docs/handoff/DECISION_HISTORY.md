# Durable decision history

This is a product-decision summary, not a transcript. It preserves the intent and corrections that materially affect future work while excluding personal data and transient private reasoning.

## 2026-08-15 — product partnership and scope

- Build the application professionally over multiple steps rather than attempting the whole vision in one prompt.
- Target broad learners aged 13+, with teenagers as the first design priority.
- Support browser now and consider desktop/mobile distribution later.
- Initial learning field: Agentic Coding from basic through advanced.
- A built-in AI is part of the long-term idea, but its purpose depends on how learners instruct, verify, and recover; it is not permission for an unsafe direct browser provider.
- English is the initial product language.
- ProofMode is the working repository/product name; naming may be revisited as a coordinated decision.

## 2026-08-16 to 2026-08-18 — evidence-first foundations

- “Make the call” established the core evidence/intervention/decision behavior.
- Minimum age 13+ and consumer learning before employer use were approved.
- React/Vite/Router was approved for the web platform; backend vendors were not selected.
- Early Casefile/Arena explorations preserved useful evidence and mission concepts, but their childish, guide-heavy, text-heavy execution was rejected.

## 2026-08-19 to 2026-08-24 — public website corrections

- The website and repeated-use app are separate experiences.
- The website may be cinematic, 3D-feeling, and interactive only when motion/media communicates the actual product.
- Generic round shapes, AI orbs, low-quality/random imagery, giant text, fake terminal theatre, and a decorative “Play proof” button were rejected.
- The first viewport must show the app and the consequence of evidence-based human intervention.
- The stronger V6 direction was restored after a weaker polish pass.
- Owner-confirmed supplied stills may be used/modified for the public website.
- GitHub Pages is the current host. `/play` remains the public app action.
- Windows/macOS installers and auto-update are future only; no fake binary or updater.

## 2026-08-25 — application blueprint

- Design first, then build each page in detail.
- Approved sequence: Today → onboarding → Learn → focused lesson → guided checkpoint → private result/replay → private progress → Profile/Settings.
- Desktop must be materially broader than mobile; mobile must become a focused sequence, not a squeezed desktop.
- Safety, security, failure states, accessibility, responsive behavior, and tests are built with each page.

## 2026-08-26 — repository operating system

- Canonical specifications, page contracts, roadmap, quality bar, approvals, handoff, and agent instructions belong in `main`.
- Root `AGENTS.md` is authoritative; root `agent.md` is a small compatibility pointer.
- Automated tests remain in `main`; exploratory review artifacts stay outside unless promoted deliberately.
- Routine implementation, repair, PR readiness, and green merging are delegated. Agents should not repeatedly ask permission inside the approved blueprint.
- Learn hub/path and the complete first lesson were then implemented and deployed as separate vertical slices.

## 2026-08-28 — first lesson complete

- “Define the outcome before delegating” is deployed.
- It uses local deterministic structural checking and five human self-checks, not fake AI grading.
- A real CSS budget failure was fixed through route-level code/CSS splitting while retaining and strengthening budgets.
- The next dependency is the guided Proof Chain checkpoint.

## 2026-08-28 — no competition and expanded continuity pack

Owner direction: remove competition from the user experience and roadmap.

Binding effect:

- no Arena, PvP, ranks, ladders, leaderboards, matchmaking, seasons, public comparison, percentile pressure, or pay-to-win in V1/V2;
- historical competition documents are superseded records, not backlog;
- motivation uses private mastery, useful practice, replay, and a clear next step;
- architecture, page specs, roadmap, quality rules, and handoff must not quietly reintroduce competition;
- a future reversal would require a new explicit owner decision and full youth-safety/privacy/fairness/UX review.

The same decision requested a comprehensive `docs/handoff/` folder covering current state, product direction, page/system maps, UX, functions/data, V1/V2, payments, media, QA/release, and glossary so another advanced agent can continue without original chat context.

## Decision discipline

- A proposal is not implementation approval.
- A mock, fixture, generated image, or historical document is not proof of availability.
- A merged green route becomes “implemented” only after its state, responsive, accessibility, security/privacy, performance, test, documentation, rollout, and rollback contract agrees.
- Update this file only for durable direction; use `docs/agent/RUN_LOG.md` for run evidence and git/PRs for exact history.
