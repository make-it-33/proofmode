# Product roadmap: V1 through V2

## Delivery rule

Build one complete vertical slice at a time. Do not parallel-build the whole vision. Every slice includes page/state contracts, broad desktop, focused mobile, accessibility, privacy/security, performance, automated tests, documentation, rollout, rollback, and green integration.

**No competition:** competition is not a future phase. It is removed from V1/V2.

## Completed foundation

- Approved cinematic public website and all information routes.
- `/play` promise and `/entry` 13+ boundary.
- Northstar deterministic mission/checkpoint foundation.
- Broad desktop/focused mobile Today workspace.
- Private local onboarding and Agentic Coding field boundary.
- Learn hub and five-band Agentic Coding path.
- First focused lesson: define the outcome before delegating.
- Strict TypeScript, unit/domain tests, Playwright/axe, deterministic state fixtures, client-boundary checks, and route-aware bundle/media budgets.
- Canonical agent instructions, specs, approvals, quality bar, run log, and continuity records.

## V1 — complete one trustworthy learning loop

### V1.1 Guided Proof Chain checkpoint — next

Route: `/app/checkpoint/outcome-before-delegating-v1`.

Use the bundled dashboard scenario. Require evidence inspection, review of a deterministic AI move, verification observations, accept/reject/modify/investigate decision, rationale, uncertainty, and outcome.

Exit: all states, no answer cues, 1920/1440/390/zoom/reduced motion, keyboard/focus/axe, no storage/network/provider/upload/execution, tests, budgets, docs, rollback, green merge.

### V1.2 Private result and replay

Route: `/app/result/:runId`.

Reconstruct the Proof Chain; highlight pivotal intervention, one strong behavior, one risk, uncertainty, and one next practice. Private/local fixture. No numeric score unless a deterministic authoritative contract exists; no rank or cohort claim.

### V1.3 Truthful private local progress

Add versioned device-local completion/resume only after checkpoint and result agree. Include migration, corrupt-data fallback, reset, honest export description, and tests. No cloud-sync wording.

### V1.4 Profile and Settings

Private guest profile based only on real evidence. Settings for appearance, density, motion, timer, audio/captions, field/goal/pace, privacy, reset/export, support, safety, and legal. Controls appear active only when behavior exists.

### V1.5 Frame band completion

Expand Frame lessons one at a time:

1. Define outcome before delegating — implemented.
2. Separate context from instruction.
3. Bound in-scope/out-of-scope files and behaviors.
4. Convert constraints into executable evidence.
5. Recover when the task contract was wrong.
6. Frame-band checkpoint and private replay.

Every lesson teaches one observable behavior and has a deterministic/offline path.

### V1.6 PWA/release hardening

Only when the app has repeat value: installable web manifest/service-worker strategy, offline content/versioning, update/recovery copy, cache invalidation, security headers where hosting allows, release notes, and production smoke. Do not imply native binaries.

### V1 exit criteria

- New learner can complete onboarding → lesson → checkpoint → result/replay → next lesson.
- Every displayed completion is real for the declared local boundary.
- No P0/P1, red CI, WCAG A/AA axe violation, mobile overflow, hidden primary action, claim mismatch, or budget breach.
- Under-13 exit, privacy language, reset, and recovery are understandable.
- Content can be versioned and rolled back.
- Product remains useful without competition, social pressure, payments, or real AI.

## V1.5 — content depth and operating tools

- Complete Direct, Verify, Recover, and Ship/Coordinate lessons in dependency order.
- Add internal versioned content-authoring schemas and blind QA checklists.
- Build deterministic scenario fixtures and accessible alternatives.
- Improve local history/replay and private export.
- Add support operations and incident/abuse processes before accepting transmitted feedback.
- Research account, AI, sandbox, payment, and native options without committing to a paid/lock-in vendor.

## V2 — approved connected product

V2 is not one launch. Each connected capability has its own approval and security gate.

### Account and sync

Private account, secure sessions, device management, recovery, consent/region policy, minimum data, authorization isolation, retention, export, deletion, backups, restore, and migration from local progress with explicit opt-in.

### Built-in AI coach

Server-only gateway, purpose-specific typed schemas, deterministic test provider, redaction, prompt-injection/tool policy, time/token/rate/cost limits, cancellation, timeout, retry, fallback, evaluations, safe telemetry, and kill switch. AI coaches/explains/simulates; it is not final scoring authority.

### Secure coding sandbox

Only after independent threat review: disposable workers, no secrets, denied-by-default network, filesystem/process/CPU/memory/time limits, dependency controls, cleanup, abuse/rate/cost controls, audit, and kill switch.

### Authoring and content operations

Content studio, role-based access, drafts, immutable publish versions, blind review, accessibility/safety QA, rollback, and provenance. Generated content needs human review.

### Premium and payments

Offer paid depth/convenience only after free core value is proven. Add server-authoritative entitlements, hosted/vendor checkout, verified idempotent webhooks, receipts, taxes/regions, renewal/cancel, refunds, chargeback/support processes, privacy/security review, and honest failures. Pricing remains undecided.

### Native Windows/macOS

Only when native capabilities materially improve learning: signed/notarized packages, least-privilege permissions, checksums, release channels, secure update metadata, staged rollout, rollback, crash/privacy policy, installer/updater tests. Mobile native requires a separate value and store-policy review.

### Future learning fields

Design, Business, Research, and Game Development each require curriculum outcomes, content/evidence schemas, lessons, checkpoints, results, accessibility, safety, and support before activation.

## Explicitly absent from V1/V2

Arena, PvP, ranks, ladders, leaderboards, seasons, matchmaking, public score comparison, direct messages, open public feed, contact upload, employer candidate ranking, hiring recommendations, intelligence/employability scoring, fake certification, targeted advertising, arbitrary non-sandboxed code execution, and pay-to-win.

A private sharing/community system may be researched only after accounts, granular consent, blocking/reporting, moderation, retention/deletion, and youth-to-adult rules are approved. It cannot introduce comparison pressure by another name.

## Per-slice checklist

1. State outcome, dependencies, non-goals, states, data/security boundary, abuse cases, analytics policy, rollout, rollback.
2. Inspect canonical docs/current main/tests.
3. Implement pure deterministic domain logic before provider/storage complexity.
4. Add appropriate unit, contract, browser, accessibility, security/abuse, and performance coverage.
5. Inspect 1920px, 1440px, 390px, zoom/text resilience, keyboard/focus, forced colors, and reduced motion.
6. Run `npm run verify` and full Playwright/axe.
7. Review claims, secrets, hidden truth, data, permissions, youth safety, cost, boundaries, and budgets.
8. Update specs, handoff, run log, approvals/ADR, issue/PR evidence.
9. Merge only green; verify `main` and deployment when applicable.
