# Mission authoring

1. Name the transferable behavior.
2. Write objective and submission contract before artifacts.
3. Build a truth map of claims, sources, uncertainty, and acceptable alternatives.
4. Select one reusable mechanic.
5. Design the AI failure and recovery opportunity.
6. Write scoring rules before polish.
7. Create strong, weak, exploit, and ambiguous test runs.
8. Blind-playtest with at least three people.
9. Calibrate time/difficulty and remove answer-revealing cues.
10. Publish an immutable version only after editorial and scoring QA.

## Standards

Use realistic fictional privacy-safe data; consistent numbers/dates/units; plausible distractors; at least one useful AI path and one meaningful verification choice; feedback that teaches process, not only the answer.

## Review roles

Author, adversarial editor, scoring reviewer, and UX/accessibility reviewer. One person may fill multiple roles early, but each checklist must be explicit.
